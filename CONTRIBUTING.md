# outshell's Coding Standards

- Use 4 spaces
- Use consistent and descriptive names for your variables, functions, parameters, structs, and files/directories
- Use DRY where appropriate
- Document all functions and structs like somewhat like google style docstrings in python
- When writting documentation, get to the point as quick as possible 
- Try to write **SIMPLE** code, rather than **CLEVER** code
- Avoid nesting where possible
- You may use Ai but make sure you proofread all the code Ai gives you
- Please read and listen to comments
- Update anything that may be out of date, inaccurate, and/or cause outshell to not function properly
- Try **NOT** to collect any user data where possible
- All .md files should be all upder-case with an underscore for multi-name files Eg: EXAMPLE_ONE.md  
- Use cammel case for multi-name functions, structs, files/directories, parameters, and variables

# Pull Requests

1) Fork/clone the repository
2) Create a branch for your changes
3) Proofread your changes
4) Open a pull request explaining:  
    - What did you change?  
    - Why you changed what you changed?  
    - What benefits OutBot will gain?  
    - Will this help users have a better experience with OutBot?  
    - Ai use  
    - How you would like to be credited
